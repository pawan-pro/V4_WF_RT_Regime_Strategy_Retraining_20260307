## Session note addendum (follow-up fix): action-count/parser parity for audit-health fields

### Root cause identified
- `last_skip_reason`/`last_error_reason` were derived via `parse_last_action_reason`, which parses `orders_placed` with JSON logic.
- `last_skip_count_24h`/`last_error_count_24h` were computed with a regex against raw JSON text.
- This created a parsing-contract mismatch: string-regex counting could miss valid events when payloads are wrapped or structurally variant, producing counts that did not reflect reason extraction.

### Exact code changes made (smallest safe fix)
- Added shared parser helper in `01_Processing/03_Realtime/10_RT_Saxo_Dashboard_Feed.py`:
  - `extract_order_events(orders_payload: Any) -> list[dict]`
  - `normalize_action_name(value: Any) -> Optional[str]`
- Updated `parse_last_action_reason` to reuse `extract_order_events` and `normalize_action_name`.
- Replaced regex-based `load_execution_action_health` count logic with parser-based action counts over the 24h trade row slice:
  - Parses each row’s `orders_placed` with `extract_order_events(...)`
  - Increments `skip_count` for normalized `action == "skip"`
  - Increments `error_count` for normalized `action == "error"`
- This keeps the 24h counting rule aligned with the latest-reason derivation and remains additive to output schema (no field/removal changes).
